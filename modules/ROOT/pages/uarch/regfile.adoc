Terminology
-----------

The key words "*MUST*", "*MUST NOT*", "*REQUIRED*", "*SHALL*", "*SHALL NOT*",
"*SHOULD*", "*SHOULD NOT*", "*RECOMMENDED*", "*NOT RECOMMENDED*", "*MAY*",
and "*OPTIONAL*" in this document are to be interpreted as described in
https://rfc-editor.org/info/bcp14[BCP 14]
{blank}[https://doi.org/10.17487/RFC2119[RFC2119]]
{blank}[https://doi.org/10.17487/RFC8174[RFC8174]]
when, and only when, they appear in all capitals, as shown here.

The term "slice" *SHALL* refer to a fixed-width, non-overlapping portion of
a word, `SLICE_WIDTH` bits wide. A word is divided into `NUM_SLICES` slices.
The exact bit range for a slice *SHALL* be interpreted as described in
requirement `REQ-REGFILE-020`.

IP Overview
-----------

A register file design for a RISC-V core. Each word is divided into fixed-width
slices. An independent slice selector is used for the read port(s) and the
write port to allow a read and write to target different slices of the
register file in the same cycle. Register 0 is hard-wired to zero on all
read ports to follow the RISC-V specification. One synchronous write port
and a configurable number of combinational read ports are provided.

Design Requirements
-------------------

[cols="1,4"]
|===
| Requirement ID | Description

| `REQ-REGFILE-010`
| The module *MUST* store stem:[\texttt{NUM\_WORDS} - 1] words,
each `XLEN` bits wide.

| `REQ-REGFILE-020`
| Slice stem:[k] of word stem:[n] *SHALL* correspond to bits
stem:[[(k+1) \cdot \texttt{SLICE\_WIDTH} - 1 : k \cdot \texttt{SLICE\_WIDTH}]]
of register stem:[n], partitioning each word into `NUM_SLICES` non-overlapping
slices each `SLICE_WIDTH` bits wide.

| `REQ-REGFILE-030`
| Register contents *MUST* be zero at most one clock cycle after the synchronous
reset (`rst_ni`) is asserted.

| `REQ-REGFILE-040`
| Writes to the register file *MUST* only occur on the rising edge of `clk_i`.

| `REQ-REGFILE-041`
| Writes to the register file *MUST* only occur when `wen_i` is asserted.

| `REQ-REGFILE-042`
| Contents of `wdata_i` *MUST* be written only to the slice selected by
`wslice_i` within the register selected by `waddr_i`. All other slices of
the target register *SHALL* remain unchanged.

| `REQ-REGFILE-043`
| The read selector `rslice_i` *SHALL NOT* affect the write port.
Read and write slice selection *SHALL* be fully independent.

| `REQ-REGFILE-044`
| Writes to register 0 *SHALL* be silently ignored, regardless of the state of
`wen_i`.

| `REQ-REGFILE-050`
| The read output `rdata_o[i]` *SHALL* be combinationally derived from the
current register state, `raddr_i[i]`, and `rslice_i`. There *SHALL NOT* be
any latency on reads.

| `REQ-REGFILE-051`
| The read output `rdata_o[i]` *MUST* reflect the slice selected by `rslice_i`
within the register selected by `raddr_i[i]`.

| `REQ-REGFILE-052`
| The write selector `wslice_i` *SHALL NOT* affect the output of any read port.
Read and write slice selection *SHALL* be fully independent.

| `REQ-REGFILE-053`
| The read output `rdata_o[i]` *MUST* be zero when `raddr_i[i]` is zero,
regardless of any prior writes to register 0.

| `REQ-REGFILE-054`
| Requirement `REQ-REGFILE-053` *SHALL* be unconditional: it *MUST* hold at
power-on without reset having been asserted, and at all times during normal
operation.

| `REQ-REGFILE-060`
| The module *SHALL NOT* implement any bypass logic. A read and write
to the same address in the same cycle *SHALL* return the value held in
the register prior to the rising clock edge of the current cycle,
regardless of whether `rslice_i` and `wslice_i` select the same slice.

Architecture
------------

The module is composed of a flop array, a combinational read network,
and a clocked write port.

=== Storage

The register array is declared as a packed 2D structure:

[source]
----
logic [NUM_WORDS-1:1][XLEN-1:0]
----

By default, this will be a stem:[15 \times 32] bit array.

=== Slice Addressing

The active slice for reads and the active slice for writes are addressed
independently, each via their respective part-select:

[source]
----
// Read
register[raddr_i[i]][rslice_i * SLICE_WIDTH +: SLICE_WIDTH]

// Write
register[waddr_i][wslice_i * SLICE_WIDTH +: SLICE_WIDTH]
----

The read slice selector `rslice_i` is shared by all read ports. The write slice
selector `wslice_i` selects the write port and is independent from `rslice_i`.
The selector inputs `rslice_i` and `wslice_i` may differ in the same cycle.

=== Read Ports

The reads are all combinational. For a read port stem:[i]:

[stem]
++++
\texttt{rdata\_o}[i] =
\begin{cases}
	0 & \text{if} \; \texttt{raddr\_i}[i] = 0, \\
	\texttt{register}[\texttt{raddr\_i}[i]][\text{slice}] & \text{otherwise}.
\end{cases}
++++

There is no read-after-write forwarding; a write is not visible on a read port
until the next cycle.

=== Write Port

Write to the registers are clocked on the rising edge of `clk_i`.
Both of the following conditions must be satisfied for a write to occur:

. `wen_i` is asserted; and
. `waddr_i` is not zero, as register 0 is write-protected.

The write operation targets only the slice selected by `wslice_i`. All other
slices of the addressed register remain unchanged.

=== Implementation Notes

The following documents implementation decisions, including intentional deviations
from standard practice and known limitations.

* The register file is implemented with a slice selector to match the width of
the datapath design.

* The register file uses independent read and write slice selectors so the
datapath can, for example, write back a lower slice while reading an upper
slice in the same cycle. This is a behavioral change from the single shared
`slice_sel_i` in version 0.2 of the regfile specification, which forced
reads and writes onto the same slice.

* There are no assertions to guard the `XLEN % SLICE_WIDTH == 0` constraint;
violating it will leave the top bits of each word unreachable.

* The write block contains a `dff-name-style` waiver to suppress a
naming convention warning from the `verible-verilog-lint` linter; the decision
was to have the array named `register`, which deviates from the project's
style guidelines.
